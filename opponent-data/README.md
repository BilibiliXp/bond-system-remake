# 对手数据池维护说明

## 文件放置位置

后续新增的对手回放 JSON 统一放在本目录：

```text
D:\新改版羁绊系统\opponent-data\
```

文件名可以自行描述流派，但扩展名必须为 `.json`。当前池中包含：

- `吴国灼烧流01.json`
- `群雄核心流01.json`
- `蜀国经验流01.json`
- `魏国召唤流01.json`

## 数据要求

每份 JSON 必须满足：

- `schemaVersion` 为 `1`；
- `status` 为 `completed`；
- 具有不重复的 `id`；
- 完整包含第 1～20 回合；
- 每回合包含 5 个阵容槽位。
- 从第 11 回合起，任何达到 5 名不同名武将的羁绊都必须写入该回合的 `unlockedFivePersonBonds`；对应 `bonds` 旧兼容字段使用 `level: 5`，网页实际按“人数 + 解锁资格”锁定 5 人效果。

这些文件只用于网页 Demo 的敌方阵容回放，不是武将、装备、计策或羁绊具体数值的权威来源。

## 更新运行时数据

新增、替换或删除 JSON 后，在项目根目录运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\build-opponent-pool.ps1
```

脚本会校验全部 JSON，并重新生成浏览器实际加载的 `opponent-data.js`。该生成文件不得手动修改。

## 抽取规则

每次开始新一局时，系统会为第 1～20 回合生成一份对手抽取表：

- 相邻两个回合不得抽到同一份数据；
- 在任意连续 10 回合的滑动窗口内，同一份数据最多出现 3 次；
- 第 N 回合使用被抽中数据的第 N 回合阵容快照；
- 第 11～20 回合的回放阵容达到 5 人羁绊时，按该羁绊的 5 人效果进入战斗；不足 5 人时仍按实际人数档位结算；
- 新一局重新抽取，本局中途不会更换已经生成的抽取表。

为了始终满足“10 回合最多 3 次”，有效数据池不得少于 4 份。运行时数据缺失或无效时，网页会退回测试骑兵阵容并在战报中注明。
